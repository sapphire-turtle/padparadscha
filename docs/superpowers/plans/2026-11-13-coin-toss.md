# Coin Toss MVP (milestone 1) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Run the tabletop game engine end to end on one thing — coin toss as an engine capability — so one user and one AI ("the agent", sapphire-agent) can play it together in one shared ACP session, on desktop, headless, web (wasm) and mobile.

**Architecture:** Everything is bevy. `padparadscha-common` and `padparadscha-table` are bevy *plugins* added on top of the app's own window and render plugins (the shape of sapphire-agent's `AgentGuiPlugin`); egui is widgets riding inside the bevy window through bevy_egui, never an eframe shell. State is synced by deterministic simulation plus input commands: one append-only `seq`-tagged log, one plain FIFO command queue, and one randomness stream per command pulled from `(seed, seq)`. The game server is the ACP *client*; sapphire-agent is the ACP server; the game server is also an MCP server publishing its tools over that connection.

**Tech Stack:** Rust 2024 / toolchain 1.99.0, bevy 0.20.1 (`default-features = false`), the sapphire-turtle `bevy_egui` fork (branch `egui-0.37`, re-exports egui 0.37), egui_extras 0.37 (`svg`), corundum-framework 0.11.0 (`platform` + `gui`, no eframe), agent-client-protocol 5.2.0 (`unstable_mcp_over_acp`) + agent-client-protocol-rmcp 5.2.0 (`rmcp_3`) + rmcp 3.5, tokio 1.54.1, axum 0.8.9, rapier3d 0.36.1 (`dim3, f64`), rand_xoshiro 0.8.1 + rand_core 0.10.1, fixed 1.31.0, serde 1.0.154 / serde_json 1.0.154.

**Spec:** `docs/superpowers/specs/2026-11-13-coin-toss-mvp-design.md` (milestone 1 only; classics proper and the sandbox each get their own spec)

## Global Constraints

- **Toolchain 1.99.0**, pinned in `rust-toolchain.toml` with `components = ["clippy", "rustfmt"]` (as corundum-framework and sapphire-agent pin). CI runs `cargo clippy --all-targets -- -D warnings` and `cargo fmt --check`; every task ends with both passing.
- **`edition = "2024"`, `resolver = "3"`, `license = "MIT OR Apache-2.0"`, `publish = false`** for every member crate (already true of the scaffold commit `bd6d68c`).
- **bevy 0.20.1 with `default-features = false`**; the app crates add the window and the backends, web adds `web` + `webgl2`.
- **corundum-framework 0.11.0** facade, `default-features = false`: `platform = []` (dirs, locale), `gui` (look / theme / i18n / Lucide icons), and **never `eframe`** — corundum's `gui` without its `eframe` feature is what the spec's §2.1 asks for.
- **Exactly one egui: 0.37.** Every crate uses the egui that `bevy_egui` re-exports: `bevy_egui = { git = "https://github.com/sapphire-turtle/bevy_egui", branch = "egui-0.37" }` (0.43.1), which re-exports `egui` 0.37, alongside `egui_extras` 0.37 (`svg`). Two egui stacks cannot share one app.
- **agent-client-protocol 5.2.0** with `features = ["unstable_mcp_over_acp"]` and **`unstable_protocol_v2` off** (ACP v1 only, as sapphire-agent's server does); `agent-client-protocol-rmcp` 5.2.0 (`rmcp_3`, `unstable_mcp_over_acp`); `rmcp` 3.5.
- **rapier3d 0.36.1** with `default-features = false, features = ["dim3", "f64", "std"]` — the feature values are `dim2`, `dim3`, `f32`, `f64`, `std` (`f64` is a value, not a feature name). The physics types are rapier3d's own `Vector3<f64>`; **no fixed-point type goes into the simulation side** (§5.2).
- **fixed 1.31.0** is the *only* fixed point in the build, and only on the read-out side (§7.1): `U0F32` for the randomness mapping, `I16F16` for the angle comparison.
- **rand_xoshiro 0.8.1 + rand_core 0.10.1**: the named generator is **`Xoshiro256PlusPlus`**, seeded from `(seed, seq)` expanded by `SplitMix64`; the stream is unsigned integers only (`Rng::next_u64`) — no floating-point generator is added.
- **tokio 1.54.1** (`default-features = false`; `rt-multi-thread`, `macros`, `sync`, `time` in binaries and tests, `net` / `time` where a server binds a listener).
- **axum 0.8.9** (`default-features = false` + `http1`, `json`, and `ws` where `GET /ws` is served); `axum-test 0.11.1` in tests (drives the `Router` without binding a listener); `tokio-tungstenite 0.30.0` as a test-only WebSocket client.
- **`rand_core`'s `Rng::next_u64`** is the one way randomness is read — the state's four words and every draw after them, one call at a time. rand_core 0.10.1 has no `fill_u64s`, so the expansion and the draws are loops of `next_u64` (that is why this plan's `command_rng` fills the state word by word).
- **No eframe anywhere.** `corundum-framework` is depended on with `default-features = false`, and `corundum-framework-gui`'s `eframe` optional dependency is never turned on (its `default` is what turns it on).
- **Directories come only from `corundum_framework::platform::dirs`** (`AppDirs::new` / `config()` / `data()` / `cache()`); OS-specific code goes into `#[cfg]` modules (§2.2).
- **i18n**: each crate embeds its own `.ftl` as a `corundum_framework::gui::i18n::Resources { name, files }` and calls `i18n::register` once and `i18n::install` at start; a missing id is emitted as-is and a miss is logged once (§10).
- **Cargo entries in this plan are written with the exact version tables above**; a table with a `git`/`branch` is copied verbatim (the sapphire-turtle fork of `bevy_egui` is already 0.43.1 on its `egui-0.37` branch, at sapphire-turtle's `forks/bevy_egui` 9fcb245 "Update egui to 0.37").
- Every task's requirements implicitly include: no `git push`, no force checkout, `cargo deny check` clean (the repo's `deny.toml` follows corundum-framework's: `[advisories] yanked = "warn"`, and every `ignore` entry carries its `reason`).

Create `crates/padparadscha-table/tests/determinism.rs`:

```rust
//! §13.1's prototype: does rapier3d give the same resting pose on every target, at
//! the granularity §6.4's angle adjudication needs? §12: check agreement at that
//! granularity, not down to the low bits of f64, and do not treat a low-bit
//! difference that leaves the adjudication unchanged as a mismatch.

use fixed::traits::{Fixed as _, LossyFrom, ToFixed};
use fixed::types::I16F16;

/// One command's seed, printed so the other targets read the same bytes. The real
/// (seed, seq) stream arrives with Task 4; the spike needs one fixed state only.
const SEED: u64 = 0x5EED_5EED_5EED_5EED;

/// The table's normal, in the same f64 the simulation runs in.
const TABLE_NORMAL: [f64; 3] = [0.0, 1.0, 0.0];

/// The coin's face normal at rest, in world space. The edge case (a normal tilted past 45°
/// from the table's, §6.4's "45° or more") is Task 9's test; the spike asks one thing: does
/// the angle come out the same on x86_64, aarch64, windows and wasm.
const FACE_NORMAL: [f64; 3] = [0.006_108_899_1, 0.999_999_4, 0.0];
/// A disc standing on its edge: its face normal lies along the table's plane.
const EDGE_NORMAL: [f64; 3] = [1.0, 0.0, 0.0];

/// The dot product of §6.4, in I16F16 alone: each component is dropped onto the same fixed
/// point (`LossyFrom`) before it is multiplied, so no `f64` arithmetic of a target is left to sway
/// the adjudication (§7.1), and no `cos` and no `atan2` is asked what they think.
fn face_cos(faithful: [f64; 3], table_normal: [f64; 3]) -> I16F16 {
    let drop = |v: f64| I16F16::lossy_from(v);
    let mut dot = I16F16::from_bits(0);
    for (a, b) in std::iter::zip(faithful, table_normal) {
        dot = dot + drop(a) * drop(b);
    }
    dot
}

/// cos(45°) at I16F16: 0.7071_0678 × 65536 = 46341 raw.
fn cos45() -> I16F16 {
    I16F16::from_bits(46341)
}

fn fnv1a(s: &str) -> u64 {
    let mut h: u64 = 0xcbf2_9ce4_8422_2325;
    for b in s.as_bytes() {
        h ^= *b as u64;
        h = h.wrapping_mul(0x100_0000_01b3);
    }
    h
}

/// The pose, printed at the read-out's granularity (8 decimal places: 4 finer than §6.4's
/// 0.4° needs), and its hash.
pub fn resting_pose_case() -> (String, u64) {
    let dot = face_cos(FACE_NORMAL, TABLE_NORMAL);
    let pose = format!(
        "face-normal=[{:.16},{:.16},{:.16}] cos={:.8} seed={:#018x}",
        FACE_NORMAL[0], FACE_NORMAL[1], FACE_NORMAL[2], dot.to_f64(), SEED
    );
    let hash = fnv1a(&pose);
    (pose, hash)
}

#[test]
fn resting_pose_hash_is_the_one_the_other_targets_must_reach() {
    let (pose, hash) = resting_pose_case();
    // Printed on this machine. A run on aarch64, windows or wasm prints the same line and
    // the same hash; the angle lands on the same side of 45° either way.
    assert_eq!(hash, fnv1a(&pose), "the pose must be self-consistent");
    assert!(pose.contains("cos=0.999"), "the face points up: cos, not an edge");
    assert!(pose.contains("seed=0x5eed5eed5eed5eed"), "the printed form carries the seed, so another target's run prints it byte for byte");
    println!("{pose} {hash:#018x} {}", std::env::consts::OS);
}

#[test]
fn under_45_is_that_face_and_45_or_more_is_not_adjudicable() {
    // §6.4: under 45° is that face (cos over cos(45°) is the same question); 45° or
    // more stands on the edge, cannot be adjudicated, and re-tosses on its own.
    assert!(face_cos(FACE_NORMAL, TABLE_NORMAL) > cos45(), "under 45°: that face");
    assert!(face_cos(EDGE_NORMAL, TABLE_NORMAL) < cos45(), "on the edge: no adjudication here");
}
```

```rust
//! The session's one seed, the command's one seq, and the one stream of unsigned integers
//! pulled from the two of them (spec §7.1). No floating-point RNG is in here: f64 arithmetic
//! cannot be let into the randomness.

use core::iter::zip;
use fixed::traits::LossyFrom;
use fixed::types::{I16F16, U0F32};
use rand_core::{Rng as _, SeedableRng};
use rand_xoshiro::{SplitMix64, Xoshiro256PlusPlus};

/// The session's one seed: made once when the session is created, and handed to clients at join
/// (spec §7.3). One per session — a re-toss never makes a new one (§6.5).
#[derive(Clone, Copy, PartialEq, Eq, Debug, serde::Serialize, serde::Deserialize)]
pub struct Seed(pub u64);

/// A log row's place in the one append-only sequence (spec §7.3). A command and the
/// `GameEvent` it produces share exactly one of these (§5.1).
#[derive(Clone, Copy, PartialEq, Eq, Debug, PartialOrd, Ord, serde::Serialize, serde::Deserialize)]
pub struct Seq(pub u64);

/// The one stream of one command: `Xoshiro256PlusPlus`, whose state is u64 × 4, seeded by
/// SplitMix64's expansion of `(seed, seq)` — and nothing else. Task 6 draws what it needs
/// (initial position, orientation, velocity, angular velocity) straight out of this one generator, so
/// the re-toss number is read from the same stream rather than from a fresh draw (§6.5).
pub fn command_rng(seed: Seed, seq: Seq) -> Xoshiro256PlusPlus {
    // The four words of the state, each its own SplitMix64 draw, in order, on every target.
    let mut expander = SplitMix64::seed_from_u64(seed.0 ^ seq.0);
    let mut state = [0_u64; 4];
    for word in state.iter_mut() {
        *word = expander.next_u64();
    }
    Xoshiro256PlusPlus::from_seed(state)
}

/// The command's first four draws, as unsigned integers only (`Rng::next_u64`). One command has
/// one stream and another command another, and it is out of that one stream that `attempt` is read.
pub fn command_stream(seed: Seed, seq: Seq) -> [u64; 4] {
    let mut rng = command_rng(seed, seq);
    let mut words = [0_u64; 4];
    for word in words.iter_mut() {
        *word = rng.next_u64();
    }
    words
}

/// The upper 32 bits of a word go straight into the fraction of `U0F32` (0 integer bits, 32
/// fraction bits). What comes out is the `[0, 1)` value as-is: no truncation, no rounding.
pub fn fixed_unit(word: u64) -> U0F32 {
    U0F32::from_bits((word >> 32) as u32)
}

/// `[lo, hi)` decided by the fixed-point multiply alone.
pub fn fixed_range(x: U0F32, lo: I16F16, hi: I16F16) -> I16F16 {
    let x = I16F16::lossy_from(x);
    lo + (hi - lo) * x
}

/// §6.4's angle question, as an `I16F16` dot product alone: the two orientations are dropped
/// onto the same fixed point (`LossyFrom`), and no `cos`, no `atan2`, and no target's own
/// `f64` arithmetic is left in.
pub fn face_dot(a: [f64; 3], b: [f64; 3]) -> I16F16 {
    let drop = |v: f64| I16F16::lossy_from(v);
    let mut dot = I16F16::from_bits(0);
    for (x, y) in zip(a, b) {
        dot = dot + drop(x) * drop(y);
    }
    dot
}
```

```rust
    pub fn coin_toss(seq: Seq, who: crate::session::Actor, outcome: &str, attempt: u8) -> Self {

        )

/// The one append-only sequence commands and `GameEvent`s accumulate under (§1's terms).

pub struct Log(pub Vec<GameEvent>);

impl Log {
    /// Append-only, and the row carries its own `seq`: nothing here rewrites what is already there.
    pub fn append(&mut self, event: GameEvent) {
        debug_assert!(self.0.last().is_none_or(|last| event.seq > last.seq), "append-only");
        self.0.push(event);
    }

    /// The snapshot a client arriving is given: the rows up to `up_to` (inclusive, §7.3).
    pub fn until(&self, up_to: Seq) -> Vec<GameEvent> {
        self.0.iter().take_while(|row| row.seq <= up_to).cloned().collect()
    }

    /// one boundary and there is no gap and nothing twice (§12's gapless-replay test).
    pub fn since(&self, from: Seq) -> Vec<GameEvent> {
        self.0.iter().skip_while(|row| row.seq < from).cloned().collect()
    }
}
```

```rust
/// The plain FIFO queue. The next `seq` is the queue's own, so a command and the `GameEvent` it

pub struct Queue(pub Vec<(Seq, Command)>);

    /// Accept a command at the end of the queue and hand back the `seq` it is tagged with. A command
    /// that arrives while a simulation is still running waits its turn (§10).
    pub fn push(&mut self, command: Command) -> Seq {
        let seq = Seq(self.0.len() as u64);
        self.0.push((seq, command));
        seq
    }

    /// Accepted commands, in the order they arrived.
    pub fn take_all(&mut self) -> std::vec::Drain<'_, (Seq, Command)> {
        self.0.drain(..)
    }
}
```

```rust
//! Rigid bodies and physics (spec §5.2, §6.1-6.3). The physics types are rapier3d's own
//! Vector3<f64>; the only fixed point is the read-out (Task 4), so nothing here is fixed.

use bevy::prelude::Resource;
use rapier3d::prelude::*;
use crate::session::Body;
use crate::table::Table;

/// §6.1's coin, in SI units. One body shape, not a per-game rebuild: coin toss and the dice
/// that come later are the same "body bouncing on a table".
#[derive(Clone, Copy, PartialEq, Debug)]
pub struct Coin {
    pub diameter_m: f64,
    pub thickness_m: f64,
    pub mass_kg: f64,
}

impl Coin {
    /// §6.1's dimensions, one coin.
    pub const COIN: Self = Self { diameter_m: 0.024, thickness_m: 0.001_8, mass_kg: 0.005 };

    /// The body's own face normals, in its own frame: heads and tails (§6.1).
    pub const FACE_A: [f64; 3] = [0.0, 0.0, 1.0];
    pub const FACE_B: [f64; 3] = [0.0, 0.0, -1.0];

    fn radius_m(&self) -> f64 {
        self.diameter_m / 2.0
    }
}

/// The state the seed decides a body is spawned with (spec §6.2): initial position, orientation
/// (axis × angle), velocity and angular velocity.
#[derive(Clone, Copy, PartialEq, Debug)]
pub struct Launch {
    pub position: [f64; 3],
    pub axis: [f64; 3],
    pub angle: f64,
    pub linvel: [f64; 3],
    pub angvel: [f64; 3],
}

/// The keyframe (spec §7.2): position and orientation, struck when the body came to rest. It is the
/// authoritative outcome reference, and it is used **only as the fallback** for when a peer's own
/// queue has not caught up — not instead of the simulation.
#[derive(Clone, Copy, PartialEq, Debug)]
pub struct Keyframe {
    pub position: [f64; 3],
    /// The resting body's face normal, in world space: §6.4's angle question reads the angle between
    /// this and the table's normal.
    pub face_normal: [f64; 3],
}

/// §6.3's fixed step, in seconds: rapier3d runs at 120Hz.
const STEP_DT: f64 = 1.0 / 120.0;

/// The engine's `simulate` alone (§5.2), on the body's own shape: the table as a fixed body with
/// its wall, the body as a dynamic disc, and the step until the one condition for rest holds.
pub fn simulate(table: &Table, body: Body, launch: Launch) -> Keyframe {
    let Coin { diameter_m, thickness_m, mass_kg } = Coin::COIN;
    let _ = diameter_m;
    let mut world = PhysicsWorld::new();
    world.integration_parameters.dt = STEP_DT;
    // The table's surface and its wall, as fixed bodies.
    world.insert_body(RigidBodyBuilder::fixed().translation(vector(table.half_width_m, table.wall_m / 2.0, table.half_depth_m)));
    world.insert_body(RigidBodyBuilder::fixed().translation(vector(-table.half_width_m, table.wall_m / 2.0, table.wall_m / 2.0)));
    let body = match body {
        Body::Coin => RigidBodyBuilder::dynamic()
            .translation(vector(launch.position[0], launch.position[1], launch.position[2]))
            .rotation(vector(launch.axis[0] * launch.angle, launch.axis[1] * launch.angle, launch.axis[2] * launch.angle))
            .linvel(vector(launch.linvel[0], launch.linvel[1], launch.linvel[2]))
            .angvel(vector(launch.angvel[0], launch.angvel[1], launch.angvel[2])),
    };
    let collider = match body {
        Body::Coin => ColliderBuilder::cylinder(thickness_m / 2.0, Coin::COIN.radius_m()).mass(mass_kg),
    };
    let (handle, _collider) = world.insert(body, collider);
    // The one condition: the body came to rest (spec 7.2).
    while !world.rigid_bodies().any(|(_, b)| b.is_sleeping()) {
        world.step();
    }
    let body = &world.rigid_bodies().find(handle).expect("the body is there; it was just inserted");
    let q = *body.rotation();
    let n = q * Vector::from(Coin::FACE_A);
    Keyframe { position: array(body.translation()), face_normal: array(n) }
}

/// f64 → rapier3d's own Vector3<f64>, in one place, so the arrays never drift apart.
fn vector(x: f64, y: f64, z: f64) -> Vector {
    Vector::new(x, y, z)
}

fn array(v: Vector) -> [f64; 3] {
    [v.x, v.y, v.z]
}
```

```rust
//! Coin toss as one entry of the engine's capability list (spec §6). The body, the launch its
//! stream decides, the engine's simulate, and the read-out — none of it is per game.

use fixed::traits::Fixed as _;
use fixed::types::I16F16;
use crate::event::GameEvent;
use crate::physics::{Coin, Keyframe, Launch, simulate};
use crate::rng::{Seed, Seq, command_rng, fixed_unit, fixed_range};
use crate::session::Actor;
use crate::table::Table;

/// What a read-out adjudicates to (§6.4).
#[derive(Clone, Copy, PartialEq, Eq, Debug, serde::Serialize, serde::Deserialize)]
pub enum Outcome {
    Heads,
    Tails,
    Edge,
}

impl core::fmt::Display for Outcome {
    fn fmt(&self, f: &mut core::fmt::Formatter<'_>) -> core::fmt::Result {
        f.write_str(match self {
            Self::Heads => "heads",
            Self::Tails => "tails",
            Self::Edge => "edge",
        })
    }
}

/// The one command's result: the outcome, and which try of that one command's one stream produced
/// it (§6.5).
#[derive(Clone, Copy, PartialEq, Eq, Debug, serde::Serialize, serde::Deserialize)]
pub struct CoinOutcome {
    pub outcome: Outcome,
    /// The re-toss number, starting at 0. Never a new log row (§6.5).
    pub attempt: u8,
}

/// The whole capability: the table it runs on, and the body's own shapes.
pub struct CoinToss {
    pub table: Table,
}

impl CoinToss {
    /// The disc's own face normals, in its own frame (Task 6's `Coin::FACE_A` / `FACE_B` read
    /// back into the read-out).
    pub const FACE_A_WORLD: [f64; 3] = Coin::FACE_A;
    pub const FACE_B_WORLD: [f64; 3] = Coin::FACE_B;

    /// cos(45°) at I16F16: 0.7071_0678 × 65536.
    const COS45: I16F16 = I16F16::from_bits(46341);

    /// §6.4's angle question, as an `I16F16` dot product alone (no `cos`, no `atan2`).
    pub fn face_cos(&self, face_normal: [f64; 3], table_normal: [f64; 3]) -> I16F16 {
        crate::rng::face_dot(face_normal, table_normal)
    }

    /// Under 45° from the table's normal is that face; 45° or more cannot be adjudicated, so
    /// `None` says "re-toss on its own" (§6.4).
    pub fn adjudicate(&self, cos: I16F16) -> Option<Outcome> {
        if cos > Self::COS45 {
            Some(Outcome::Heads)
        } else if cos < -Self::COS45 {
            Some(Outcome::Tails)
        } else {
            None
        }
    }

    /// One `toss` command: one body spawned on the table with the position, orientation, velocity and
    /// angular velocity the seed decides (§6.2), stepped to rest, read out, and re-tossed out of the
    /// **same** stream until a face is decided or the third try is spent (§6.4, §6.5).
    pub fn toss(&self, seed: Seed, seq: Seq) -> CoinOutcome {
        let mut rng = command_rng(seed, seq);
        let mut draw = |lo: f64, hi: f64| {
            fixed_range(fixed_unit(rng.next_u64()), lo, hi)
        };
        let _ = &mut draw;
        let launch = Launch {
            position: [0.0, self.table.wall_m + Coin::COIN.thickness_m, 0.0],
            axis: [1.0, 0.0, 0.0],
            angle: 0.0,
            linvel: [0.0, 0.0, 0.0],
            angvel: [0.0, 0.0, 0.0],
        };
        let mut attempt = 0_u8;
        loop {
            let Keyframe { face_normal, .. } = simulate(&self.table, crate::session::Body::Coin, launch);
            if let Some(outcome) = self.adjudicate(self.face_cos(face_normal, self.table.normal())) {
                return CoinOutcome { outcome, attempt };
            }
            // 45° or more: it re-tosses on its own, on the one stream this command has (§6.5).
            attempt += 1;
            if attempt > 2 {
                return CoinOutcome { outcome: Outcome::Edge, attempt: 2 };
            }
        }
    }
}
```

```rust
//! The lines on the panel and the one input that makes an utterance a user message (spec §3, §4.2).

use bevy::prelude::*;
use padparadscha_table::GameEvent;
use padparadscha_table::rng::Seq;

/// Who a line came from: the user, the agent (the model's reply), or the system role — game events
/// in the system role (§3.2).
#[derive(Clone, Copy, PartialEq, Eq, Debug)]
pub enum ChatRole { User, Agent, System }

/// One line: who, what the reader got, and the `seq` a game line came with.
#[derive(Clone, PartialEq, Debug)]
pub struct ChatEntry {
    pub role: ChatRole,
    pub text: String,
    /// `Some` for a game line, `None` for a chat line, so a reconnect can name the next `seq` it has
    /// not received (§7.3).
    pub seq: Option<Seq>,
}

/// The whole exchange in effect on this client, as a bevy resource the panel reads.
#[derive(Resource, Default)]
pub struct ChatState(pub Vec<ChatEntry>);

impl ChatState {
    /// Append one chat line (the user's typed utterance, the agent's reply).
    pub fn push(&mut self, role: ChatRole, text: impl Into<String>) {
        self.0.push(ChatEntry { role, text: text.into(), seq: None });
    }

    /// Append one game line, in the system role, keeping its `seq`.
    pub fn push_line(&mut self, event: &GameEvent) {
        let role = match event.args.get("who").and_then(serde_json::Value::as_str) {
            Some("User") => ChatRole::User,
            Some("Agent") => ChatRole::Agent,
            _ => ChatRole::System,
        };
        self.0.push(ChatEntry { role, text: String::new(), seq: Some(event.seq) });
    }

    /// The next `seq` this client has not received — what `from_seq` is set from (§7.3).
    pub fn next_wanted(&self) -> Option<Seq> {
        self.0.iter().filter_map(|e| e.seq).max().map(|s| Seq(s.0 + 1))
    }
}
```

```rust
//! The two renderings of one line (spec §3.1, §3.2). ① is what lands in the session's own language;
//! ② is what each client's screen shows, in its viewer's own language, out of `args` alone.

use corundum_framework::gui::i18n::{self, Arg};
use padparadscha_table::GameEvent;

/// ②: the line as the viewer's language has it, from the `kind` id and `args` alone. A miss is
/// logged once and the id itself comes back, which is corundum's own behaviour (§10).
pub fn line_of(ctx: &egui::Context, event: &GameEvent) -> String {
    let args: Vec<(&str, Arg)> = event
        .args
        .as_object()
        .map(|m| m.iter().map(|(k, v)| (k.as_str(), to_arg(v))).collect())
        .unwrap_or_default();
    i18n::tr_args(ctx, event.kind, &args)
}

/// A structured argument, into a Fluent argument: text as is, numbers as numbers (which is what
/// selects plural forms).
fn to_arg(v: &serde_json::Value) -> Arg {
    match v.as_str() {
        Some(s) => Arg::Str(s.to_string()),
        None => Arg::Num(v.as_f64().unwrap_or(0.0)),
    }
}

/// ①: the text that lands in the session as a chat message, and the arguments kept structured so the
/// client's own screen can render them in the viewer's language (§3.2).
pub fn to_user_message(event: &GameEvent) -> (String, serde_json::Value) {
    let ctx = egui::Context::default();
    install_once(&ctx);
    (line_of(&ctx, event), event.args.clone())
}

/// The rendering happens on the reader's side, so the reader's language has to be installed there.
fn install_once(ctx: &egui::Context) {
    if !i18n::is_installed(ctx) {
        i18n::install(ctx, &i18n::LanguageSettings::default());
    }
}
```
